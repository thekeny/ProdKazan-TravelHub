# Правила проекта

## О проекте

TravelHub — приложение для планирования поездок и сохранения их истории: маршрутов, событий, фотографий, билетов и заметок. Описание продукта находится в `docs/`. При заданном `NEXT_PUBLIC_API_URL` аккаунты и поездки загружаются с бэкенда через SDK и серверный прокси Next.js. Без URL доступен прежний локальный режим. Клиентские проверки маршрутов не являются авторизацией: доступ к серверным данным проверяет бэкенд.

Стек: Next.js (App Router, Turbopack), React 19, TypeScript, Tailwind CSS v4, Base UI / Shadcn, Ky. Проверки и форматирование — Biome, тесты — Vitest.

## Структура

- `src/app/` — маршруты, страницы, layouts; `src/middleware.ts` — middleware Next.js.
- `src/components/` — UI по областям: `auth`, `trips`, `landing`; `dashboard` — оболочка приложения, `layout` — общие компоненты раскладки, `ui` — переиспользуемые примитивы.
- `src/configs/` — единый источник маршрутов и URL (`paths/`), констант и статических данных (`consts/`), общих доменных типов (`types/`).
- `src/providers/` — общее состояние и контексты; `src/hooks/` — пользовательские React-хуки; `src/lib/` — чистые функции, утилиты и работа с хранилищем.
- `src/api/generated/` — SDK и типы из OpenAPI; `src/api/hey-api.ts` — настройки HTTP-клиента; `openapi-ts.config.ts` — настройки генерации.
- `src/tests/` — тесты, повторяющие структуру `src/`.

## Организация кода

- Перед изменениями изучай связанные файлы и существующие решения. Следуй принятым именам и стилю, переиспользуй компоненты и функции.
- У каждого файла должна быть понятная ответственность. Страницы оставляй тонкими: они собирают интерфейс из компонентов. Самостоятельные части интерфейса выноси в отдельные файлы внутри соответствующей области `components/`.
- Отделяй отображение от логики: повторяемую React-логику выноси в хуки, чистые вычисления и преобразования — в `lib/`, общее состояние — в провайдеры. Не собирай страницу, данные, хранение и бизнес-логику в одном компоненте.
- Деление определяй по смыслу и ответственности, без формальных лимитов строк. Не дроби простые выражения на файлы и не создавай универсальные абстракции без реальной необходимости.
- Маршруты, URL, повторяемые значения, лимиты, статические списки и данные примеров выноси в тематические файлы `configs/paths/` и `configs/consts/`. Не дублируй их в компонентах и не создавай один общий файл для несвязанных данных.
- Общие доменные типы размещай в тематических файлах `configs/types/`. Типы пропсов и другие типы, нужные только одному компоненту или модулю, оставляй рядом с ним. Сгенерированные API-типы используй из SDK без ручного дублирования.
- Подписи разделов оформляй классом `.section-label` (11px, sentence case), без uppercase и широкого трекинга. Даты поездок выводи через `formatTripDates` — компактный диапазон вида «7–10 ноября 2026».
- Используй строгие типы; избегай `any`, необоснованных приведений типов, магических значений и дублирования логики. Давай переменным и функциям имена, отражающие назначение.
- Соблюдай границы Server и Client Components. Добавляй `"use client"` только там, где нужны хуки, обработчики событий или браузерные API.
- Обрабатывай ошибки, загрузку и пустые состояния на соответствующем уровне. Комментариями объясняй только неочевидные причины и ограничения, а не очевидные действия кода.

## Ограничения и проверка

- Текстовые файлы используют окончания строк LF, закреплённые в `.gitattributes`. Сгенерированный SDK исключён из форматирования Biome; обновляй его только генератором.

- Карта дашборда использует Leaflet / React Leaflet и загружается только на клиенте. Настройки тайлов и атрибуция находятся в `src/configs/consts/map.const.ts`; URL тайлов можно переопределить через `NEXT_PUBLIC_MAP_TILE_URL` (при смене провайдера обновляй атрибуцию). Не скрывай атрибуцию OpenStreetMap и не добавляй фоновую загрузку тайлов для офлайн-доступа.
- События хранятся внутри поездки через `TravelProvider`; старые поездки без `events` считаются пустыми. Время события — локальная строка `YYYY-MM-DDTHH:mm` без преобразования в часовой пояс браузера; события через полночь относятся ко дню начала.
- Типы событий задаются чипсами при создании путешествия и в его настройках (`TripValues.eventTypes`). Enter добавляет тип, пробел остаётся пробелом. В форме события выбирается один тип этого путешествия через `TextSelect` (`EventValues.customType`). Удаление типа из списка путешествия сохраняет его в старых событиях. В API поддержки пока нет: каталог серверных поездок (`tripEventTypes`) и выбранные типы событий (`eventTypes`) сохраняются через `remote-preferences` по ID пользователя, поездки и события. После появления API подключить их к SDK. Поле `type` остаётся для совместимости с API и историей; новые события отправляются с `other`, отсутствующий `customType` означает старый тип.
- Изменение только списка типов существующей серверной поездки сохраняется локально без PATCH поездки; при ошибке записи в браузере состояние в памяти не обновляется.
- Тип можно добавить прямо в форме события через `addEventType`: он сразу сохраняется в каталоге поездки и выбирается в форме, даже если затем отменить событие. Черновик названия входит в подтверждение закрытия; во время добавления закрытие и отправка блокируются. Поддержка кастомных типов в актуальной OpenAPI проверена 2026-11-08: пока отсутствует.
- Материалы формы события разделены вкладками «Фото» и «Документы». Категория одновременно определяет список превью и вид новых загрузок; ссылка на билет находится в документах. Лимит общий для всех материалов события. Загрузчик вызывает скрытое файловое поле через кнопку и возвращает фокус без прокрутки; окно формы закреплено, прокручивается только его содержимое. На пакет файлов показывается одно уведомление; ошибки отдельных файлов не отменяют успешные загрузки.
- Меню аккаунта в мобильной шапке и на страницах поездок объединяет настройки и выход в обоих режимах. Выход использует общий `useAccountLogout`, переход после очистки сессии выполняет `AuthGuard`; переход после входа — `useAuthForm`, без повторного редиректа из обработчиков. Удаление поездки доступно из меню действий и настроек через `useTripDeletion` и общий `TripDeleteConfirmation`; подтверждение поверх формы — на z-index 70.
- Точки маршрута (`points`) и перемещения (`legs`) хранятся в самой поездке. Событие ссылается на точку через `pointId`; при удалении точки связанные перемещения удаляются, а события остаются без места. Старые события с вложенным `place` мигрируют в точки при чтении хранилища.
- Материалы события (`materials[]`) содержат только метаданные и хранятся вместе с событием. Файлы изображений лежат в IndexedDB через `src/lib/material-storage.ts`; загрузка, проверка типа/размера и сжатие — в `src/lib/material-upload.ts` и `src/lib/image.ts`. Не переносите файлы в `localStorage` и не блокируйте сохранение события ошибкой загрузки фотографии.
- `readStateWithReport` в `src/lib/travel-storage.ts` читает состояние best-effort: повреждённые поездки, точки, перемещения и события пропускаются, а валидные данные сохраняются. Ссылки на удалённые точки очищаются, а не роняют чтение всего состояния.
- Разделы `dashboard/gallery` и `dashboard/documents` показывают материалы активной поездки, сгруппированные по дням. Фильтрация идёт по `material.kind` (`photo` / `document`); в документах также выводятся ссылки `bookingUrl`. Заголовок материала ведёт на `/dashboard?day=…&event=…`.
- Обзор поддерживает deep links `?day=YYYY-MM-DD&event=<id>`: выбранный день и открытая карточка синхронизируются с URL. Лента дня (`DayFeed`) — отдельный диалог со списком событий и перемещений; панель маршрута — тоже диалог с ловушкой фокуса.
- Для обратной связи используй глобальный `react-hot-toast` (`role="status"`) и `actionToast` для действий пользователя с состояниями промиса и `StorageWarning` для предупреждений о повреждённых данных. Не сбрасывай `storageWarning` автоматически при сохранении — только по действию пользователя.
- Оверлеи карты (таймлайн, пустое состояние) держи на `z-20`, панели — на `z-30/40`, диалоги — на `z-50`, формы поверх панелей — на `z-[60]`. Не возвращай таймлайну `z-[1000]`: он перекрывает диалоги.
- Виды транспорта и их стили на карте объявлены в `src/configs/consts/transport.const.ts`; цвета — в переменных `--transport-*` в `src/app/globals.css`.
- Обзор поездки занимает всю рабочую область: карта растягивается на оставшуюся высоту, под ней — таймлайн дня с часовой шкалой. Положение «сейчас» вычисляет `positionAtTime` из `src/lib/travel-route.ts`, оно же подсвечивается на карте. Цвета типов событий — `EVENT_COLORS` в `src/configs/consts/events.const.ts` и переменные `--event-*`.

- `src/providers/travel-provider.tsx` выбирает локальный или серверный провайдер. `remote-travel-provider.tsx` обновляет данные только после успешного ответа API; после частичного удаления перечитывает состояние сервера. В локальном режиме работа с браузерным хранилищем изолирована в `src/lib/travel-storage.ts`: не обновляй состояние в памяти, если запись не удалась.
- Ошибки восстановления серверной сессии, кроме подтверждённого 401, показывают общий `ServerError`, а не переход на логин. Код 500 на этом экране показывается только при HTTP-статусах 500–599; остальные сбои загрузки отображаются без кода. При действиях пользователя только ответы 5xx заменяют интерфейс этим экраном; остальные ошибки обрабатываются формами и уведомлениями. Повторная загрузка страницы восстанавливает состояние с сервера.
- SDK использует `/api/backend`; прокси `src/lib/backend-proxy.ts` добавляет `/api/v1` к корневому URL бэкенда, хранит access/refresh токены в HttpOnly cookie и повторяет запрос после refresh. Редирект на тот же адрес с изменением завершающего `/` выполняется внутри прокси однократно, с сохранением метода и тела для 307/308; токены не передаются на другой origin. Не передавай токены в клиентский JS или localStorage. Длинные int64 ID передавай через `apiId` без преобразования в JavaScript number.
- Адаптеры API находятся в `src/lib/travel-api.ts`. События передаются без часового пояса; перемещения требуют смещения, поэтому адаптер добавляет фиксированное `Z`, сохраняя локальные цифры времени без преобразования через часовой пояс браузера. Время в UI остаётся `YYYY-MM-DDTHH:mm`.
- Совместный доступ к серверной поездке реализован через `tripsGenerateCode`, `tripsJoinTrip` и `tripsGetTripByIdCollaborators`. Прокси пропускает `/trips/{id}/code/generate`, `/trips/code/redeem/{code}` и `/trips/{id}/collaboratrs`; при обновлении SDK проверяйте allowlist в `src/lib/backend-proxy.ts`. Код приглашения ограничен по числу использований, публичной ссылки без аккаунта и удаления участника пока нет. Генерацию кода в интерфейсе видит только владелец по данным `TripCollaborators`; права на редактирование и удаление поездки обязан проверять бэкенд. В локальном режиме методы совместного доступа недоступны.
- API пока не поддерживает изменение имени и описания существующего перемещения, а также загрузку файлов материалов событий. Обложка серверной поездки — HTTP(S)-ссылка или файл через SDK. Материалы остаются в IndexedDB; их метаданные и активная поездка сохраняются отдельно по ID серверного пользователя через `src/lib/remote-preferences.ts`. Старые локальные поездки автоматически на сервер не отправляются.
- `npm run test:backend` проверяет работающий Next.js (`TEST_APP_URL`, по умолчанию `http://localhost:3001`) и реальный бэкенд: создаёт временный аккаунт и поездку, проверяет CRUD, код приглашения, список участников и refresh, затем удаляет созданные записи. Не запускай его против чужого окружения без разрешения.
- Не редактируй `src/api/generated/` вручную; для обновления используй `npm run openapi`.
- Проверяй изменения соразмерно задаче: `npm run lint` — стиль и статические проверки, `npm test` — тесты, `npm run build` — сборка при изменениях, влияющих на неё. Добавляй содержательные тесты изменённой логики; не пиши тесты, лишь повторяющие реализацию.
- При добавлении архитектурных решений, инструментов или соглашений обновляй этот `AGENTS.md`.

## Бренд и типографика

- PWA кеширует оболочку, страницы и статические ресурсы только в production. API и RSC не кешируются; офлайн-переходы по ссылкам используют HTML-навигацию. Серверные поездки и профиль сохраняются в IndexedDB через `src/lib/offline-cache.ts`, без токенов; выход и подтверждённый 401 очищают снимок. Офлайн доступен только просмотр, при возвращении сети страница перечитывает сервер. Баннер позволяет проверить связь вручную.
- PWA и push используют одну регистрацию `public/sw.js` со scope `/` через `src/lib/app-service-worker.ts`. В dev воркер обслуживает push без кеширования и перехвата запросов; офлайн-кеширование работает только в production. Ожидание регистрации и активации ограничено 15 секундами.
- Push доступны только серверным аккаунтам: `PushProvider` восстанавливает разрешённую подписку, баннер предлагает подключение, настройки позволяют отключить и отправить тест. Разрешение запрашивается только при нажатии. SDK использует `publicKey`, `keys.p256Dh`; удаление и тест требуют серверного `subscriptionId` через `apiId`. Привязка `{userId, endpoint, id}` и отказ хранятся отдельно в `push-storage`, без токенов и копий ключей. Перед выходом и при 401 подписка браузера отключается; операции сериализуются, при наличии Web Locks — между вкладками. Ссылки уведомлений ограничены текущим origin.
- Тайлы кешируются только при `NEXT_PUBLIC_MAP_OFFLINE_CACHE=true` для явно разрешающего это провайдера (`NEXT_PUBLIC_MAP_TILE_URL`, `NEXT_PUBLIC_MAP_ATTRIBUTION`). Публичные тайлы OpenStreetMap никогда не кешируются сервис-воркером. Сохраняются только просмотренные тайлы, максимум 300, без фоновой загрузки областей; точки и линии маршрутов доступны без подложки.

- Логотип и иконка — исходные файлы `public/brand-logo.png` и `public/brand-icon.png`. Не перерисовывай маскота и не заменяй исходники самодельным SVG.
- Caveat (`font-display`) используется только для крупных акцентных заголовков. Небольшие заголовки, даты, подписи, основной текст и интерфейс — Lora (`font-sans`). В модальных окнах и боковых диалоговых панелях заголовки также используют Lora. Шрифты подключены локально из `public/fonts/`.
- Бумажная текстура лежит в `public/paper-texture.png`; для фонов используй классы `.paper-texture` и `.flow-background`, а не сторонние изображения.

## Цвета интерфейса

- Палитра TravelHub объявлена в `src/app/globals.css` и доступна через тему Tailwind v4: `primary` (#4F8A68), `green` (#7BAE7F), `water` (#8ECAE6), `background` (#F7F5EF), `surface` (#FFFFFF), `road` (#E6D8B5), `border` (#D8D8D8), `text` (#2F3A33).
- Всегда используй цветовые токены Tailwind (`bg-surface`, `text-foreground`, `border-border`, `bg-primary`), семантические алиасы и модификаторы прозрачности. Не задавай HEX/RGB/HSL или стандартные цвета Tailwind непосредственно в компонентах. Производные оттенки определяй в теме через переменные; для ошибок используй `destructive`.
- Для основных кнопок и активных элементов используй `primary-strong` — затемнённый вариант брендового цвета, который проходит контраст с белым текстом. `primary` остаётся акцентным цветом для линий, иконок и подсветки.
- Для Leaflet и другого кода вне Tailwind используй CSS-переменные темы (`var(--primary)`). Исключение — форматы, не поддерживающие CSS-переменные (например, web manifest): их значения синхронизируй с палитрой.

- Общие поля `Input` и `Textarea` находятся в `components/ui`; внутри `Field` указывайте `data-field-control` для регистрации, ошибок и фокуса. Вариант `Button plain` сохраняет оформление специализированных карточек и переключателей.
- Браузерные проверки: `npm run test:e2e` (Playwright/Chromium), локальный сервер на порту 3100 без API. Эталоны лежат в `e2e/snapshots`; обновляйте их только после проверки визуальных различий.
- Проверки push в браузере запускаются отдельно: `npm run test:e2e -- --config=e2e/push.config.ts`. Используется серверный режим с подменой SDK-запросов и Push API, без обращения к настоящему бэкенду и отправки реальных уведомлений.

- Настройки пользователя показывают серверный профиль. Смена пароля выполняется через SDK (`PUT /auth/me/password`, `currentPassword` и `newPassword`); форма запрашивает текущий пароль и двукратный ввод нового. Ответ 403 означает неверный текущий пароль и показывается у поля. Изменение имени недоступно, пока в API нет соответствующего метода. В локальном режиме `renameAccount` переименовывает аккаунт с сохранением поездок, смена пароля недоступна.
- Общий `DialogPopup` добавляет крестик. Закрытие изменённых форм требует подтверждения через `useDiscardConfirmation`; во время сохранения и загрузки закрытие блокируется.

- Формы используют React Hook Form через `useFormValues` и `FormProvider`; ошибки полей из `src/lib/form-validation.ts` отображаются через `Field name="…"`. Формы имеют `noValidate`, не используют HTML-предупреждения и блокируют повторную отправку при ожидании.
- Ограничения ввода объявлены в `src/configs/consts/validation.const.ts` и одинаковы в полях, формах и обоих провайдерах. Новые и изменённые даты допускаются от сегодняшнего дня до +10 календарных лет включительно, сегодня — с 00:00. Неизменённые сохранённые даты разрешены через `ValidationContext.initial`; проверки чтения истории не зависят от текущего дня и новых лимитов ввода. Границы рассчитываются в `src/lib/input-validation.ts` без сдвига локального времени поездки.
- `Field` показывает ошибку только при её наличии, без резерва пустой высоты: 12px/16px, отступ 4px; расстояние между группами полей — 16px. Пользовательский текст переносится через `overflow-wrap: anywhere` (`.user-text`), без `truncate` и `line-clamp`; описания сохраняют переводы строк. Для выбора точек с пользовательскими названиями используйте `TextSelect` с `data-field-control` внутри `Field`, чтобы сохранялись перенос, регистрация поля, фокус и доступные ошибки.
- Удаление подтверждается общим `ConfirmDelete`, включая материалы и обложки; подтверждения над формами имеют z-index 70, анимированные `dialog-backdrop` / `dialog-popup` и `forceRender` у backdrop вложенного диалога. Часовая шкала целиком помещается по ширине панели; горизонтальные жесты не передаются карте или браузерной навигации.
- Файловые обложки серверных поездок загружаются через SDK (`PUT /trips/{trip_id}/cover`, JPEG/PNG/WebP до 5 МиБ после сжатия). Изображения читаются через авторизованный `/api/backend`; прокси передаёт бинарные тела без преобразования в текст. Удаление — PATCH с `cover: null`. Старые обложки из IndexedDB читаются для совместимости.
