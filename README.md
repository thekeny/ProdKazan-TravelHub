Планировщик путешествий: маршрут на карте, события, перемещения, фотографии, билеты и заметки в одной хронологии.

## Запуск

Нужен Node.js 22+ (в CI и Docker используется Node 24).

```bash
npm ci
cp .env.example .env.local
npm run dev
```

Приложение откроется на `http://localhost:3000`.

Укажите адрес бэкенда в `.env.local`, например `NEXT_PUBLIC_API_URL=http://localhost:8000`. SDK отправляет запросы на `http://localhost:8000/api/v1`; генератор использует `http://localhost:8000/api/v1/openapi.json`. Завершающий `/api/v1` в переменной также поддерживается без дублирования. После изменения переменной перезапустите dev-сервер; для production пересоберите приложение. При пустом значении используется `/api/v1` текущего origin; браузерные тесты подменяют эти запросы.

### Переменные окружения

| Переменная | Назначение |
| --- | --- |
| `API_URL` | Больше не используется приложением. |
| `NEXT_PUBLIC_API_URL` | Адрес бэкенда для SDK и генерации OpenAPI. `/api/v1` добавляется автоматически. Задаётся до запуска или сборки. |
| `NEXT_PUBLIC_MAP_TILE_URL` | Необязательный URL тайлов карты. По умолчанию OpenStreetMap. При смене провайдера обновите атрибуцию в `src/configs/consts/map.const.ts`. |
| `NEXT_PUBLIC_MAP_ATTRIBUTION` | Атрибуция тайлов, если она отличается от значения по умолчанию. |
| `NEXT_PUBLIC_MAP_OFFLINE_CACHE` | `true` включает кеширование просмотренных тайлов, если провайдер это разрешает. Публичные тайлы OpenStreetMap не кешируются. |

## Скрипты

```bash
npm run dev        # dev-сервер
npm run build      # production-сборка
npm start          # запуск собранного приложения
npm run lint       # Biome: стиль и статические проверки

npm run openapi    # перегенерация SDK из OpenAPI
```

## Что реализовано

- создание, редактирование и удаление поездок с обложкой;
- точки маршрута с выбором на карте и координатами;
- перемещения между точками с видом транспорта и временем;
- события поездки с типами, временем, точкой, описанием и ссылкой на билет или бронь;
- переключение дней и режим «Все дни» на карте;
- карточка события с материалами и быстрыми действиями;
- карточка точки на карте со связанными событиями и добавлением события на месте;
- лента дня со списком событий и перемещений по порядку;
- таймлайн с часами, переносом через полночь и переходом к событию;
- deep links `?day=…&event=…`: день и открытая карточка сохраняются в URL;
- материалы события: JPEG, PNG и WebP, сжатие на клиенте, превью и удаление;
- галерея и раздел «Билеты и документы» со ссылками на брони;
- проверка пересечений событий и перемещений с переходом к конфликту;
- совместный доступ к серверной поездке: код-приглашение, присоединение по коду и список участников;
- уведомления о сохранении и удалении, предупреждение о повреждённых данных;
- чтение `localStorage` с восстановлением: валидные поездки сохраняются, повреждённые записи пропускаются;
- error boundary, `not-found`, скелетоны загрузки и метаданные страниц;
- офлайн-просмотр серверных данных в PWA.

## Ограничения

- Материалы событий пока не сохраняются на сервере и не синхронизируются между устройствами.
- Нет PDF-документов: поддерживаются только JPEG, PNG и WebP.
- Нет публичной ссылки на просмотр без аккаунта: совместный доступ работает по коду для авторизованных пользователей.
- Нет удаления участника из поездки.
- Нет автоматического построения маршрута по дорогам и расчёта времени в пути.
- Нет push-уведомлений и напоминаний.
- Типы событий хранятся локально и не передаются в API.
- `npm run test:e2e` проверяет серверный интерфейс с подменой API и вёрстку; сценарии реального бэкенда проверяются `npm run test:backend`.

## Архитектура

- `src/app/` содержит маршруты и layouts.
- `src/components/` делит UI по областям: `dashboard`, `trips`, `materials`, `layout`, `ui`.
- `src/configs/` хранит пути, константы и общие типы.
- `src/lib/` содержит чистые функции, валидацию, хранение, API-адаптеры и прокси.
- `src/providers/travel-provider.tsx` выбирает локальный или серверный провайдер.
- `src/providers/remote-travel-provider.tsx` работает с API, сессией, офлайн-снимками и совместным доступом.
- `src/hooks/` содержит React-хуки, включая загрузку blob-URL материалов из IndexedDB.
- `src/tests/` повторяет структуру `src/`.

Материалы события описываются метаданными в `localStorage` (`materials[]`), а файлы лежат в IndexedDB. Сохранение события не зависит от загрузки фотографии: при ошибке изображения событие всё равно сохраняется.

## Совместный доступ

Владелец серверной поездки открывает действия с поездкой → «Совместный доступ» и создаёт код приглашения с ограничением по числу использований. Попутчик вводит код в разделе «Поездки» → «Присоединиться по коду». После присоединения поездка появляется в его списке; если бэкенд вернул её в обновлённом списке, она сразу становится активной.

Совместный доступ использует SDK напрямую, включая историческое написание `/trips/{id}/collaboratrs`.

## CI и деплой

`.gitlab-ci.yml` выполняет:

- `lint` (Biome);
- `typecheck` (`tsc --noEmit`);
- `test` (Vitest);
- `build:next` (production-сборка);
- сборку Docker-образа и ручной деплой на production из master.

Dockerfile упаковывает собранное приложение (`.next/standalone` и `.next/static`). `NEXT_PUBLIC_API_URL` нужно задать в окружении задания `build:next`: адрес встраивается в браузерный код при сборке, изменение переменной только в готовом контейнере его не обновляет. Smoke-check контейнера проверяет `/`; доступность бэкенда проверяется по `${NEXT_PUBLIC_API_URL}/api/v1/health`.

## Офлайн-просмотр в PWA

В production (`npm run build`, затем `npm start`) приложение регистрирует service worker. Нужен HTTPS либо localhost. Перед поездкой откройте приложение с интернетом и просмотрите нужные разделы: оболочка и последние успешно загруженные поездки сохранятся на устройстве. После потери сети они доступны для просмотра, включая события, точки, перемещения и локальные материалы из IndexedDB. Новые данные без подключения не загружаются, изменения не ставятся в очередь.

Верхний баннер «Вы оффлайн» показывает пояснение при наведении и фокусе; нажатие проверяет соединение. При возвращении сети приложение перезагружается и проверяет серверную сессию. Выход и подтверждённый 401 очищают снимок аккаунта. При запрете браузерного хранилища приложение продолжает работать онлайн, но офлайн-снимок может быть недоступен.

По умолчанию карта использует публичные тайлы OpenStreetMap, запрещающие офлайн-использование. Без сети сохраняются точки и линии маршрутов; подложка не гарантируется. Для сохранения просмотренных участков подключите провайдера, разрешающего офлайн-кеширование, и задайте перед сборкой:

```dotenv
NEXT_PUBLIC_MAP_TILE_URL=https://your-tile-server.example/{z}/{x}/{y}.png
NEXT_PUBLIC_MAP_ATTRIBUTION=Attribution required by your provider
NEXT_PUBLIC_MAP_OFFLINE_CACHE=true
```

Кеш ограничен 300 просмотренными тайлами. Области и дополнительные масштабы заранее не скачиваются. Переключатель не включает кеширование публичных тайлов OpenStreetMap.
