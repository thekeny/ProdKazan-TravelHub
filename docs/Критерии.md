# Критерии для Backend-жюри

| Критерий | 0 баллов | 1 балл | 2 балла |
|---|---|---|---|
| Архитектура и готовность к релизу | Команда не может объяснить архитектуру системы, её зависимости и процесс вывода в продакшен. Не понимает потенциальных проблем при развёртывании и интеграциях. | Команда понимает архитектуру и основные этапы релиза, может объяснить взаимодействие компонентов, но не проработала отдельные риски: конфигурацию окружений, миграции данных, обработку сбоев или откат изменений. | Команда обосновывает архитектурные решения, понимает процесс вывода в продакшен: развёртывание, конфигурацию, интеграции, миграции, обработку сбоев и откат. Может объяснить потенциальные риски и способы их минимизации. |
| Качество инженерной реализации | Проект невозможно воспроизводимо запустить или проверить. Отсутствуют необходимые инструкции, автоматизация сборки и тестирования. | Есть инструкции, базовый CI/CD, документация API и юнит-тесты. Основные функции работают, но проверка требует ручных действий или выявляет незначительные ошибки. | Автоматизированы сборка, тестирование и развёртывание. Есть документация API, тестовые данные, юнит- и интеграционные тесты основных сценариев. Функциональность стабильно работает и легко проверяется. |
| Наблюдаемость и диагностика | Логирование и мониторинг отсутствуют либо не позволяют определить состояние системы и причины ошибок. | Есть информативные логи и базовые метрики. Состояние системы можно оценить, но диагностика проблем требует значительных ручных усилий. | Настроены сбор логов и метрик, информативные дашборды (например, Grafana), отслеживание ошибок и алерты. Команда может оперативно обнаруживать и диагностировать проблемы. |
| Техническая оригинальность | Реализованы только типовые решения, нестандартные технические возможности отсутствуют. | Есть интересное техническое решение или дополнительная возможность на Backend, но её сложность, оригинальность или практическая ценность ограничены. | Реализовано оригинальное, технически нетривиальное решение, которое работает, приносит пользу продукту и демонстрирует высокий уровень инженерных навыков. |
| Общее впечатление | Проект оставляет негативное впечатление. | Нейтральное впечатление, проект не выделяется. | Проект оставляет положительное впечатление. |

# Критерии для Frontend+Mobile-жюри

| Критерий | 0 баллов | 1 балл | 2 балла |
|---|---|---|---|
| Работоспособность | Интерфейс ломается или не связан с бекендом | Часть данных в интерфейсе на моках, или работа с бекендом неоптимальная, или часть функционала не завершена | Интерфейс стабилен и согласован с данными на бекенде |
| Отсутствие ошибок | Ошибки на большинстве экранов | Встречаются ошибки - визуальные, логические, технические | Интерфейс работает без ошибок |
| UI | Слабый дизайн, элементы не сочетаются | Типовой, не запоминающийся интерфейс | Авторская проработка UI-решений |
| UX | Есть запутанная фича, или множество замечаний | Интерфейс логичен, но есть точечные замечания | Интуитивно понятный интерфейс без замечаний |
| Вопросы от комиссии | Нет понимания | Есть общее представление | Есть четкое понимание |

# Критерии для Продакт-жюри

| Критерий | 0 баллов | 1 балл | 2 балла |
|---|---|---|---|
| Полнота функционала | Основные функции не реализованы. | Реализованы ключевые функции, но продукт неполный. | Все заявленные функции работают, покрыты основные сценарии. |
| Проработанность бизнес-сценариев | Бизнес-сценарии не проработаны. | Частично проработанные сценарии, но без деталей. | Полноценные бизнес-сценарии с пользовательскими историями. |
| Презентация бизнес-ценности | Команда не презентовала бизнес-ценность. | Команда презентовала бизнес-ценность, но без аргументов. | Команда презентовала бизнес-ценность и потенциал развития с обоснованием. |
| Дополнительные функции | Дополнительные функции не реализованы. | Есть дополнительные функции, но они не добавляют ценности. | Дополнительные функции хорошо реализованы и решают конкретные потребности ЦА. |
| Общее впечатление по блоку | Проект оставляет негативное впечатление. | Нейтральное впечатление, проект не выделяется. | Проект оставляет положительное впечатление. |

# Общие критерии

| Критерий | 0 баллов | 1 балл | 2 балла |
|---|---|---|---|
| Качество выступления | Выступление неструктурированное, команда не смогла понятно представить проект, продемонстрировать результат | Команда понятно представила проект и продемонстрировала результат, но выступлению не хватает последовательности, уверенности | Команда провела логичное, убедительное выступление, наглядно продемонстрировала работу продукта, уложилась в регламент |
| Общее впечатление от проекта | Проект оставляет негативное впечатление. | Нейтральное впечатление, проект не выделяется. | Проект оставляет положительное впечатление. |

Проекты должны соответствовать ряду обязательных критериев.  
При их невыполнении применяются штрафные санкции, снижающие полученные баллы.

| Критерий | Штраф |
|---|---|
| Решение не задеплоено (нет APK, если мобильная разработка) | -20% баллов |
| Несоответствие минимальному набору критериев, описанных в кейсе | -30% баллов |
