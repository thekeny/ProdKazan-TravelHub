# Интеграция с бэкендом

SDK обращается напрямую к `${NEXT_PUBLIC_API_URL}/api/v1`. В `.env` задайте адрес бэкенда, например `NEXT_PUBLIC_API_URL=http://localhost:8000`, до запуска dev-сервера или production-сборки. Префикс `/api/v1` добавляется автоматически; старое значение с этим префиксом также поддерживается без дублирования. Next.js не проксирует API. При пустом значении запросы идут на `/api/v1` текущего origin; e2e использует это для подмены браузерных запросов.

Для отдельного origin бэкенд должен разрешать origin фронтенда в CORS с credentials и корректно настраивать refresh-cookie для используемых доменов.

Конфигурация находится в `src/api/hey-api.ts` и `src/configs/paths/backend.path.ts`. Запросы используют `credentials: "include"`. Refresh-cookie устанавливает бэкенд; access token хранится только в памяти страницы и передаётся как Bearer. После перезагрузки сессию восстанавливает `/auth/refresh`. Одновременные 401 используют общий refresh и один повтор с исходным телом. Web Locks сериализуют обновления между вкладками, когда доступны. Ошибка проверки пароля не очищает текущую сессию.

Старые cookie прокси больше не используются: после перехода нужно войти снова. `API_URL` не используется; `NEXT_PUBLIC_API_URL` задаёт адрес и для браузерных запросов, и для генерации SDK по `${NEXT_PUBLIC_API_URL}/api/v1/openapi.json`. Не редактируйте сгенерированный SDK вручную.

Защищённые обложки загружаются SDK как Blob и показываются через временные object URL, которые освобождаются при смене изображения или размонтировании. Поездка хранит стабильный путь бэкенда. Внешние изображения не получают токены. API-запросы и токены исключены из офлайн-кеша.

Callback `/api/v1/integrations/google-drive/callback` обслуживает бэкенд. Поиск мест остаётся обработчиком Next.js `/gateway/places/search`.

Проверки: `npm run lint`, `npx tsc --noEmit`, `npm test`, `npm run build`, `npm run test:e2e`. Дополнительные браузерные наборы используют `e2e/push.config.ts` и `e2e/integrations.config.ts`. `npm run test:backend` требует явный `TEST_APP_URL` и создаёт временные записи: запускайте только против разрешённого окружения.

## Подключённые сценарии

- Регистрация, вход с паролем, восстановление сессии, выход и чтение профиля.
- Список, создание, изменение и удаление путешествий, включая название, описание, даты и ссылку на обложку.
- Чтение и CRUD точек, событий и перемещений; ссылки бронирования и привязка событий к точкам.
- Совместный доступ: создание кода-приглашения, присоединение по коду и список участников поездки. Используются `POST /trips/{trip_id}/code/generate`, `POST /trips/code/redeem/{code}` и `GET /trips/{trip_id}/collaboratrs`; прокси пропускает эти пути.
- Удаление точки с удалением связанных перемещений и сохранением событий без места; удаление содержимого перед удалением поездки. Эти операции состоят из нескольких запросов: при сбое уже выполненные удаления не откатываются, а интерфейс перечитывает состояние сервера.

Идентификаторы бэкенда превышают `Number.MAX_SAFE_INTEGER`. Адаптер сохраняет их строками и передаёт десятичные строки даже там, где OpenAPI описывает число. Приём таких значений проверен на работающем API. Единственное приведение типа в `apiId` нужно для несовпадения сгенерированных типов с фактическим int64-контрактом.

События и перемещения требуют времени со смещением: адаптер добавляет `:00Z` и сохраняет цифры часов, а не пересчитывает их по часовому поясу браузера. При чтении время возвращается в локальный формат `YYYY-MM-DDTHH:mm`. Модель часовых поясов отдельных городов пока отсутствует.

## Ограничения текущего API

В схеме нет изменения имени пользователя, загрузки файлов и метаданных материалов, удаления участника поездки и изменения описания существующего перемещения. Смена пароля доступна через `PUT /auth/me/password`. Соответствующие поля интерфейса показывают ограничение. Сервер принимает HTTP(S)-ссылку на обложку и файл через `PUT /trips/{trip_id}/cover`.

Фотографии и документы остаются в IndexedDB этого браузера. Метаданные материалов и выбор активной поездки хранятся в отдельном пространстве `travelhub.remote.<userId>`. Они восстанавливаются после повторного входа в этом браузере, но не синхронизируются между устройствами. Старые локальные аккаунты и поездки больше не читаются приложением и автоматически на сервер не отправляются.

SDK обновлён генератором по полученной OpenAPI-схеме. `npm run openapi` загружает свежую схему с настроенного бэкенда. Локальный снимок `openapi.json` не коммитится; для генерации без сети положите его в корень проекта и выполните `npx.cmd openapi-ts --input ./openapi.json`.

## Проверка

Обычные проверки: `npm run lint`, `npm test`, `npm run build`.

Vitest и Playwright проверяют прямую авторизацию SDK, обновление сессии, бинарные загрузки и ошибки доступа.

Во время первого прогона вложенных сущностей обнаружилось, что сервер запрещает удалять непустую поездку. До исправления очистки на бэкенде остались тестовая поездка `1568610886538672011` с двумя точками и событием и её временный аккаунт. Пароль был случайным и не сохранялся, поэтому удалить эти записи теперь сможет администратор бэкенда. Все последующие прогоны очистили свои данные успешно.
